# Agent harness redesign review

28 September 2026. This review is about the player client and its evaluation, not a change to game rules. Match numbers below come from completed rows in [`agents/pi/benchmarks.json`](../agents/pi/benchmarks.json) or explicitly identified incomplete raw trials. Automated bot games do not establish human-level play or numerical balance.

## What our trials actually show

- In normal-speed games against seven non-LLM practice bots, Pi Luna has been on the winning side in five of six completed rooms; Pi Qwen in one of four. Qwen's one Germany victory earned +164.79 Prestige, while its other three completed normal-speed Pi runs earned −100. Codex Qwen has two completed normal-speed losses. The clients and prompts changed during this sequence, so these counts cannot rank harness variants causally.
- The interrupted v5 Germany Qwen run recorded 54 accepted orders by its last saved game snapshot at tick 941, yet Germany then controlled zero provinces. Tool validity alone was not enough. Its runner made 28 completed decisions, reported 2.99 million tokens (2.36 million cache-read), and had eight rejected game orders at the last save. There is no final score for this run, and it remains outside the scored ledger.
- The interrupted v5 Luna run hit its 120-second model-response cap on five of seven completed decisions. The normal game clock continued during these calls. A longer context window or another detailed read tool cannot by itself solve that timing problem.
- [`board`](../agents/board.js) already reduces a late Qwen observation from about 74 KB to 4 KB, but it is still mostly province rows. The model must turn those rows into a legal, valuable choice. [`strategic_options`](../agents/strategic-options.js) is separate and optional; Qwen used it only twice in the interrupted v5 trace. The binary fresh-versus-persistent session choice either loses strategic continuity or carries a growing transcript. The raw record has tool calls and actions, while the game snapshot has events, but neither links each model decision to its later strategic outcome or preserves a per-turn decision note.
- Our full-game comparisons mix changing prompts, Pi MCP versus Codex shell access for Qwen, divergent bot reactions, and a live clock. They can reveal failures, but a single same-seed result cannot isolate why score moved. The current paused fixed task tests three specified orders; it does not test strategic choice.

## What other teams have built

| Primary source | Verified mechanism | Transfer and limit |
|---|---|---|
| [AI Diplomacy code](https://github.com/GoodStartLabs/AI_Diplomacy) and [AAAI 2026 paper](https://ojs.aaai.org/index.php/AAAI/article/view/41067) | Gives the model engine-enumerated legal orders, nearby opportunities and threats, phase results, relationships, and private context. Its Critical State Analysis branches saved positions and repeats one phase 30–120 times. The paper reports a Devstral-Small prompt variant moving from 3/10 to 9/10 wins as France; this is a small comparison, not a guaranteed rate. | Make our *decision view* actionable and replay pivotal positions many times. Their loop waits for all players before advancing a phase; Council's live tick must continue while an agent thinks. |
| [PLAP / Skill-RTS](https://github.com/AI-Research-TeamX/PLAP) and [paper](https://arxiv.org/abs/2509.13127) | A slow LLM planner selects parameterized strategic skills; a fast state-checking executor handles MicroRTS steps. The authors report a Qwen2-72B variant beating a strong scripted opponent. | Test a small client-side intent/executor layer only after a decision-view baseline. Any executor must recheck the ordinary recipient-filtered observation and submit through the same public actions, reservations, and limits. This result does not transfer to our 27B Qwen or rules. |
| [CivAgent](https://github.com/fuxiAIlab/CivAgent) and [paper](https://arxiv.org/abs/2502.20807) | Separates strategic skill choice from legal action execution and uses counterfactual simulation while respecting game visibility. | Offer read-only forecasts and compare decisions in saved positions. Never expose hidden bot state to the player view. |
| [Orak](https://github.com/krafton-ai/Orak) | Configures game, input modality, model, and agent module separately for repeatable ablations across multiple games. | Keep model, decision view, memory, and scheduler as independent experiment variables. We need no new game runtime dependency to do this. |

## Proposed sequence

1. **Freeze a baseline and capture a private trajectory.** For each decision record the visible state fingerprint, tool calls, accepted/rejected actions, elapsed time, and the next observed change in industry, territory, armies, alliance, and Prestige projection. Keep messages and raw reasoning in ignored `data/` only; publish aggregates without private text. This will tell us whether Qwen's accepted orders actually improve its position.
2. **Build one recipient-filtered decision view.** Keep the existing separate MCP action tools. Add a compact read that joins current board, command budget, recent action outcomes, and bounded feasible choices: directly reachable targets with available source troops and war prerequisites, payable developments, current votes/offers, and side economy gap. It should expose assumptions and IDs, not a hidden-policy ranking or a giant dump. The model still decides which action to take.
3. **Test at critical states before full matches.** Save several public-seat snapshots from early expansion, first war, alliance invitation, threatened capital, and late victory race. In an isolated test fixture, give the model the same frozen visible position under each view. Score legal action, time to first accepted action, token use, and short-horizon economy/survival after applying the action to a private engine clone against the same bot policy. Repeat across multiple country/seed positions. The fixture has no public advance-time endpoint; full live rooms remain the final test.
4. **Replace transcript accumulation with verified memory.** Carry a short strategic note plus a searchable private event log of actual outcomes. Update the note from the next observation, rather than treating an accepted march as a capture. Keep the model's workspace file tools available. Test this against persistent and fresh baselines; do not assume that shortening context improves play.
5. **Only then consider a parameterized executor.** If decision views reduce invalid calls but Qwen still takes too long or issues low-value tactical moves, compare a small planner/executor client with direct MCP control. Its actions must use the same HTTP API and command budget as every other player. Measure whether it improves score as well as latency; a zero-error bot that loses is not success.
6. **Run paired normal-speed matches.** Rotate country and combat seed, keep one service per model uncontended, and compare Pi with Codex on the same model. Report individual Prestige, team-win rate, industry trajectory, accepted/rejected orders, failed calls, total and uncached tokens, first action, mean/capped turn time, and diplomacy. Keep quick games as integration checks. Require repeated gains across countries before saying Qwen wins consistently.

The priority is a better decision surface and cheaper, repeatable diagnosis. More prose in the rules prompt, a larger context window, or a new visual alone has not demonstrated a Qwen win-rate improvement here.
