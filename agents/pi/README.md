# Pi benchmark harness

This package measures one model at a time: a Pi (or Codex CLI) seat, usually in an isolated room against seven practice bots, recorded as aggregate benchmark rows. To put several CLI agents (Codex, Grok, Hermes) into one live room next to human players, use [the playtest harness](../playtest/README.md) instead. Both use the same Council MCP server (`agents/mcp.js`): the same tools, `decision_view` and seat `inbox`, the same server validation and limits as every other player.

This optional package gives one Pi agent a Council seat through the public HTTP API. It connects to the existing Council MCP server and exposes its game tools to Pi (`tool-set.js`): `board`, `news`, `inbox`, `observe`, `map`, `preview`, `march`, `turn_around`, `rally`, `develop`, `declare_war`, `offer_peace`, `accept_peace`, the alliance tools, `send_message`, `after_action_report`, `replay_state` and `standings`. Vision-capable profiles also get `view_map`, which returns the exact board data plus a colored PNG. Room setup tools are filtered out for this already joined seat. In a decision-view match, `decision_view` is the one state read: `map`, `observe`, `board` and the post-match report/replay/standings tools are left out. Pi also has three workspace tools (`read_file`, `write_file`, `run`); workspace files persist per model alias under ignored `agents/pi/workspace/`. The run tool uses Bubblewrap with only that workspace writable, no host home or match database mounted, and no network. Every order goes through the same MCP definition, server validation and rate limits as other players.

The harness starts a private loopback server with a separate SQLite file, registers the chosen player, fills seven seats with built-in non-LLM practice bots, starts the match and plays until the saved result exists or the run limit is reached. The prompt states the goal: your alliance must hold 60% of the world's industry for 90 s, or have the most industry at the deadline; you must still own a province at the finish to share an alliance win, and your own industry is your score. Each match turn embeds the current authenticated game view (see `--turn-view`; the decision view leads with the seat inbox: unread messages to you and offers awaiting your answer, not marked read) and asks for a short batch of orders; the Council tools remain available for details and actions. Once the seat is eliminated, both episodic runners stop spending model turns and poll for the final result. It does not join or modify any LAN room. Run artifacts and game credentials live in ignored `data/pi/` with owner-only permissions.

`--task fixed` starts the isolated room with its clock paused and asks the model to issue three given legal orders (march, declare war, march). It uses ordinary Council HTTP validation and no public time-control endpoint. It measures order accuracy, failed calls, reported tokens and time to the third accepted order, not playing strength.

```bash
npm ci --prefix agents/pi
npm --prefix agents/pi run play -- --model qwen --country britain --preset quick --max-minutes 12
npm --prefix agents/pi run play -- --model luna --country britain --preset standard --max-minutes 35
node agents/pi/play.js --model qwen --country britain --url http://127.0.0.1:3107 --match ROOM --max-minutes 50
node agents/pi/codex-play.js --preset quick --max-minutes 12
node agents/pi/codex-play.js --access cli --preset quick --max-minutes 12
node agents/pi/codex-play.js --model luna --access mcp --turn-mode episodic --preset standard --max-minutes 35 --max-turn-seconds 240 --decision-interval-ticks 30
node agents/pi/play.js --model qwen --task fixed --preset standard --max-minutes 6 --max-turn-seconds 300
node agents/pi/codex-play.js --model qwen --access cli --task fixed --preset standard --max-minutes 6
```

**Live seat in a shared room.** `--url` and `--match` join an existing normal-speed room (for example one a human created in the browser) as a public agent instead of creating an isolated bot match. The runner waits in the lobby until the host starts, then plays with the same turn loop; `--max-minutes` counts from the start of play. Its seat credential lives in a stable ignored file under `data/pi/live/`, so the same model, country and room reconnect after a restart. The host need not hold a seat: a seatless host can keep some practice seats with `POST /api/games/ROOM/bots {"count": 2}` (retrying adds no more), start from the lobby's **Start and watch** button, or run `agents/pi/start-when-full.js` (with `COUNCIL_URL`, `COUNCIL_MATCH` and the host's `COUNCIL_SESSION`) to start once every country is taken.

For a normal-speed paired trial, use one model service at a time and give both clients the same country, turn view and combat seed:

```bash
node agents/pi/play.js --model qwen --country germany --preset standard --max-minutes 35 --max-turn-seconds 120 --session-mode persistent --decision-interval-ticks 30 --turn-view decision --combat-seed trial02
node agents/pi/codex-play.js --model qwen --access cli --turn-mode episodic --country germany --preset standard --max-minutes 35 --max-turn-seconds 120 --decision-interval-ticks 30 --turn-view decision --combat-seed trial02
```

## Options

The model alias is resolved from the ignored root `.env` (or process environment). `PI_DEFAULT_MODEL` selects the default alias. For each alias, set `PI_MODEL_<ALIAS>_PROVIDER` (`openai-completions` or `openai-codex`), `ID`, `PLAYER_NAME` (at most 40 characters) and `CONTEXT_WINDOW`. Local OpenAI-compatible profiles also need `BASE_URL` and `TRANSPORT=chat_completions`. Optional fields are `NAME`, `MAX_TOKENS`, `THINKING_LEVEL`, `REASONING`, `INPUT_IMAGES`, `THINKING_FORMAT`, `CHAT_TEMPLATE_KWARGS` (JSON when `THINKING_FORMAT=chat-template`), `OFF_REASONING_EFFORT` and `API_KEY`. For a server that needs an explicit `reasoning_effort: "none"` to act without a reasoning phase, set `REASONING=true`, `THINKING_LEVEL=off` and `OFF_REASONING_EFFORT=none` (not with `THINKING_FORMAT`). Set `INPUT_IMAGES=true` only for an endpoint that accepts image input; `view_map` needs ImageMagick's `convert` on the MCP host. See [the example config](.env.example). No model names, endpoints or keys belong in the client source. OAuth profiles read the existing Codex login in memory; no token is copied into this repo.

- `--preset standard` uses the normal 30-minute clock; `quick` scales all game timings together. `--max-turns` defaults to 80. The final console line names the ignored JSON result file; a nonzero exit code means the match did not finish or the model client failed.
- `--turn-view tools|board|decision` (default `decision`, both runners): `tools` sends only the tick and a short reminder, so the agent reads state through the tools; `board` embeds the compact board; `decision` embeds the board plus your industry gap to the 60% line, a ranked frontier of neighbouring targets, possible partners and delivered non-chat outcomes since the previous turn. The view and interface version (`tools-turn-v2`, `board-turn-v8`, `decision-turn-v6`) are saved in the raw run; compare results only within one version. `decision-turn-v6` keeps the v5 rejected-call guidance and puts the inbox, score, ready developments and frontier first in the turn view. Earlier versions remain labeled in the ledger.
- `--max-turn-seconds` (default 120) aborts an overlong model response, keeps accepted orders, and starts the next turn with a fresh view. A provider's `503 Loading model` is treated as a delay (wait 5 s, retry; stop after 24 in a row); other model errors stop after three consecutive turns. Read-only observations and reviews retry transient network errors up to three times; orders are never resent automatically.
- `--decision-interval-ticks` (default 30) waits until that much game time has passed since the response began before the next turn; a no-order response also waits at least five real seconds. It changes only the test client's cadence, not the game clock.
- `--session-mode fresh` (default) creates a new Pi model context each turn while keeping its workspace; `persistent` keeps the conversation. A built-in Pi extension replaces bulky old tool results and old turn views in each model request, leaving the saved transcript intact.
- `--combat-seed` fixes the room ID used by deterministic combat rolls. For paired trials give both runners the same seed, country, session mode and timing; the models' different decisions still create different games, so rotate seeds for a win-rate estimate.
- Codex `--turn-mode continuous` (default) is one long response for a whole match; `episodic` gives Codex the same turn prompt and cadence as Pi and resumes its saved session each turn. Resumed Codex turns report cumulative usage, so the exporter uses the last snapshot. If a response times out or fails, token and turn-time fields stay unknown.

Each raw match run also records a private `positionLog` entry before every model turn: tick, owned provinces, own and alliance industry, gap to the 60% line, side rank, alliance size and members, frontier target count, active wars and decision-view size. The benchmark importer publishes only tick, own and alliance industry, and owned-province count, plus the authoritative final own industry. Compare the industry curve with accepted orders and the final result to tell slow execution from choices that lose ground. Pi's `turnLog` also records each turn's provider stop reason and a coarse error category (loading, connection, timeout, HTTP, other); a missing token value means the provider did not report it, not zero.

The Codex runner uses Council MCP by default; `--access cli` offers the game's public CLI instead (including `decision [CURSOR]`), for local models that cannot call MCP tools in Codex. That shell can also send direct HTTP requests; the ledger labels the observed path (`shell HTTP`, `CLI + direct HTTP`, `shell fallback`). `--model luna` copies the current Codex login into its ignored private test home. The game database is hidden from Codex by Bubblewrap.

The currently tested Qwen service uses the Unsloth `Qwen3.8-27B-UD-Q4_K_XL.gguf` artifact and advertises `qwen3.8-27b-unsloth-q4-xl`; the Pi alias's model ID and endpoint come from the ignored root `.env`, and the Qwen Codex runner reads the same profile. The local 5090 service now uses a 204,800-token slot: its idle host RAM fell from about 24 GB to 10 GB after the change, and a proxied completion and `/props` check passed. For self-hosting, start `serve-unsloth-q4.sh` with `QWEN_GGUF_PATH` and `LLAMA_SERVER_BIN` set (`QWEN_MODEL_ID` overrides the alias); `QWEN_CTX_SIZE` defaults to 204800 and accepts 200000–262144. The script uses q8 key/q5 value cache, one slot and full GPU layers (`QWEN_GPU_LAYERS` adjusts). The package does not download weights. Council's main package remains free of runtime dependencies.

An OpenRouter profile uses the same local `.env` mechanism. For Space Bunny, set `PI_MODEL_SPACE_BUNNY_PROVIDER=openai-completions`, `PI_MODEL_SPACE_BUNNY_BASE_URL=https://openrouter.ai/api/v1`, `PI_MODEL_SPACE_BUNNY_ID=stealth/space-bunny-alpha`, `PI_MODEL_SPACE_BUNNY_PLAYER_NAME=Space Bunny Alpha Pi`, `PI_MODEL_SPACE_BUNNY_CONTEXT_WINDOW=1000000`, `PI_MODEL_SPACE_BUNNY_API_KEY` to your own key, and `PI_MODEL_SPACE_BUNNY_TRANSPORT=chat_completions`. The key stays in the ignored, owner-only `.env`; run it with `--model space_bunny`. A Pi turn has a hard deadline plus a short abort grace: an unresponsive turn makes the run incomplete, so it cannot enter the benchmark ledger as a completed win.

## Benchmark ledger

After a completed run, publish only its aggregate metrics to the tracked ledger. The importer refuses unfinished games and never copies endpoints, credentials, model messages or raw tool payloads. Each match row records the seat's `result` (win, draw or loss) and final `industry`, accepted and rejected orders, failed tool calls, tokens and turn timing:

```bash
node agents/pi/bench.js qwen|luna|deepseek|external [--revision GIT_HASH] data/pi/<completed-run>.json
node agents/pi/bench-playtest.js data/playtest/<finished-room>
node agents/pi/task-bench.js qwen|luna data/pi/<completed-task>.json
node agents/pi/serve-bench.js   # open http://127.0.0.1:8001/
```

[bench.html](bench.html) reads [benchmarks.json](benchmarks.json) and [task-benchmarks.json](task-benchmarks.json). It plots outcomes and metrics by run date and each seat's own industry by game tick, with model, harness, room type, country and seed filters. The match ledger contains only the current v6 map. The Pi/Codex and Grok/Hermes/Codex CLI importers refuse unfinished games and another map; the latter imports a finished `agents/playtest` room's private `run.json`, `report.json`, per-seat `turns.jsonl` and `mcp.jsonl`, then publishes only allowlisted aggregate fields. Future CLI playtests record the map ID and a position sample before each model turn. Pre-v6 rows remain in git history and their observations remain in `docs/PLAYTEST.md`; they are not comparable with v6 games. The fixed-order task ledger is separate.

The report server has an explicit five-file allowlist: the page, its script and the two aggregate ledgers. Set `COUNCIL_BENCH_HOST` and `COUNCIL_BENCH_PORT` to share it on a chosen interface. It does not serve private workspaces, match databases or raw transcripts.

A rejected Pi MCP order counts as both a rejected order and a failed call, while a Codex shell command can exit successfully after the game rejects its order; compare rejected orders for game validity. Quick rooms run the whole clock 6× faster, so they test integration and latency. For a playing-strength claim, use repeated normal-speed rooms, rotate the country, and report results and industry with first-action latency and accepted/rejected orders. A single bot room cannot establish strategic balance or human enjoyment, and the seat's `model` label is self-declared.
